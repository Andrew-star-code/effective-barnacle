### Находки при подъёме WeKnora в dev (14.11.2026)

Проверено запуском (UI и API, учётка из `deploy/compose/.env.example`):

- Признак `is_default` в `builtin_models.yaml` не задаёт модель встроенным агентам: у «Quick Answer» и «Smart Reasoning» в новом пространстве пустой `model_id`, чат отвечает «Agent не готов». Значит, раскладка (`provision`, этап 1–2) должна проставлять модель агентам каждого личного пространства — через `PUT /api/v1/agents/{id}` это работает.
- Режим агента со включёнными базами знаний требует модель реранжирования; без `rerank` в dev-стеке «Smart Reasoning» не запускается. Временно в dev у агента выключены базы (`kb_selection_mode: none`). Нужен `rerank` на CPU (§18.1) — следующий шаг этапа 0.
- Непереведённые строки при `DEFAULT_LOCALE=ru-RU`: «Go to configure →», «Edit Agent», «Model Config», «Basic Info», «Select Agent», «Built-in Agents», «Setup needed», названия встроенных агентов в подписи поля ввода («Smart Reasoning»), описания агентов приходят с бэкенда на английском. Вход в P-08/P-07 (этап 2).
- Ссылки на github.com и weknora.weixin.qq.com на странице входа — убрать вместе с остальным лишним (§17.2).

Профиль `builtin_models.ollama.yaml` (`qwen3.5:9b`, `bge-m3`) добавлен; проверка на реальной модели — после загрузки моделей.

## Решения по вопросам к плану (13.11.2026)

Вопросы найдены при разборе SPEC и сверке с кодом WeKnora; решения приняты заказчиком в тот же день и внесены в SPEC (ревизия 2.1, §0.2 и §23.1, решения 26–32). Утверждения SPEC «проверено в коде» перепроверены на теге `v0.9.0` — подтвердились все.

| № | Вопрос | Решение | Где записано |
| --- | --- | --- | --- |
| В-1 | В SPEC был закреплён `cbdcebab` — HEAD ветки `main`, на 207 коммитов новее тега | Закреплён тег `v0.9.0` (`f17ee8a8`); подмодуль переключён | SPEC §1, ADR 0001 |
| В-2 | Contributor читает промпт агента и создаёт своих агентов — скрытый репорт обходится | Guard-модель — первая линия и MUST; скрытый репорт и P-04 — этап 13 (★) | SPEC §10.6, ADR 0013 |
| В-3 | P-01 как миграция в форке конфликтует с нумерацией миграций WeKnora | Шаг `provision --search-index` в `corp-ext` | SPEC §11.2, §16.2, ADR 0014 |
| В-4 | Слот одновременной генерации снимался опросом раз в 15 секунд — ложные отказы | Чат-эндпоинты идут через прокси `corp-ext` | SPEC §14.3, ADR 0008 |
| В-5 | Связь с AD только по email; при смене email WeKnora создаёт дубликат | Ключ — `objectGUID`; `corp-ext` обновляет `users.email` | SPEC §6.1, §7.4, §16.2, ADR 0016 |
| В-6 | Перезагрузка nginx для блок-листа IP требовала прав на Docker-сокет | Блок-лист в Redis, проверка в `auth_request` | SPEC §15.4 |
| В-7 | Celery синхронный при асинхронном коде | taskiq с брокером Redis | SPEC §4, ADR 0015 |

Цена решений: исключений из правила «`corp-ext` не меняет БД WeKnora» стало четыре вместо двух (SPEC §16.2), а `corp-ext` оказался на пути потока ответа чата.

Замечания без решения:

- P-02 читает `corp.user_profiles` из Go-кода WeKnora — ядро начинает зависеть от нашей схемы; для пулл-реквеста в апстрим источник значений придётся абстрагировать.
- `JWT_SECRET` общий с `corp-ext` (HS256): владелец секрета может и выпускать токены. Отражено в ADR 0012.
- Ссылки на карточки моделей в SPEC §3.3 частично ведут на вторичные источники (`dell.huggingface.co`, `sotaverified.org`, Википедия). Параметры моделей и флаги vLLM перепроверить по первоисточникам перед бенчмарком.
- `corp-admin`: TypeScript 7 несовместим с `vue-tsc`; мажорные версии выровнены с фронтендом WeKnora (TS 6, Vite 7, Pinia 3, vue-router 4). `openapi-typescript` 7 формально просит TS 5 (предупреждение peer), генерация работает.
- Среда разработки: Makefile рассчитан на Linux-оболочку. На Windows — WSL2 (в Ubuntu 24.04 уже есть `make`, `uv`, Python 3.12; нужны Node и pnpm).

## Демо-сценарий каркаса

```bash
make install                      # зависимости и хуки
SKIP_IMAGES=1 make check          # линт, типы, тесты, сборка фронтенда, проверка документации
make dev-up                       # Postgres, Redis, fake-llm, corp-ext (нужен запущенный Docker)
curl -s localhost:8000/health     # {"status":"ok","service":"corp-ext",...}
curl -s localhost:8001/v1/chat/completions -H 'content-type: application/json' \
  -d '{"messages":[{"role":"user","content":"[[scenario:thinking]] привет"}]}'
cd services/corp-admin && pnpm dev   # http://localhost:5174/corp-admin/ — дашборд с версией corp-ext
# WeKnora: http://localhost:8080, учётка — WEKNORA_DEV_* из deploy/compose/.env.example
# (один раз зарегистрировать в UI). В «Быстрый ответ» выбрать модель fake-chat в настройках агента,
# затем: «[[scenario:thinking]] привет» — блок размышлений и ответ стримом.
# Реальная модель (нужны ollama pull qwen3.5:9b и bge-m3):
WEKNORA_MODELS_FILE=builtin_models.ollama.yaml make dev-up
```
